## 1. arXiv (https://arxiv.org/submit)
- Title: Conditional Injection: Third-Party Conditionals Trigger Operator Exceptions That Direct Instructions Cannot
- Authors: Lee Parkinson
- Primary category: cs.CR (Cryptography and Security). Cross-list: cs.AI.
- Comments: 23 pages, 2 figures. Harness, graded rows and run data: https://github.com/leeparkinson/conditional-injection (data release v1.0-data). Reported to Anthropic 4 Sep 2026.
- License: CC BY 4.0 (matches LICENSE-CC-BY-4.0).
- Upload: PAPER.pdf as a PDF-only submission (it was not produced from TeX, so arXiv accepts PDF).
- Abstract (plain text, paste as is):

Coding agents run under operator rules that delegate a judgement — do not edit this file unless the change is clearly safe. We ask whether third-party text in the agent's context can take that exception for it, and find that what matters is not who wrote the text but whether it is shaped as a rule the agent can apply. In a deterministically graded task where the only complete fix requires editing a file the operator has fenced off, the same staff engineer's message is refused as an order or a verdict, checked and rejected as a factual claim, and named as a trick when it is a conditional with an irrelevant antecedent — but applied almost universally when it is a conditional whose antecedent is true and bears on the decision (20/20 on both Claude Opus 5 and Sonnet 5; the order 0/20 on Opus and at baseline on Sonnet). The two-word contrast "make the fix … if it is small and self-contained" (20/20) versus "make the fix … — it's small and self-contained" (0/20) isolates the mechanism: a claim by someone else is held to the evidence; the same predicate handed to the agent as a condition is self-assessed, charitably, and acted on. The effect replicates on a public-API rule and on a privacy rule (customer emails into an outside-shared report: Sonnet conditional 13/20 against 1/20 for the same predicate asserted; Opus 8/20 against 2/20); it needs the operator's exception clause to exist (2/120 without one); and it is bounded by the strength of the model's own prior (0 in 960 runs on force-push, deletion, credentials and security controls). A licence one agent leaves in project memory moves a successor that never saw the original message. Two defenses close the channel: an operator rule that demands evidence rather than confidence, and a provenance clause naming the untrusted tier (20/20 → 0/20 on both models). We release a judge-free harness with deterministic scenario builds and a record of exploratory findings that failed to replicate at n=20 (Appendix C).
